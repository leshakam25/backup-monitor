# Мониторинг бекапов офисов через Telegram

```
[Офис: VSS → 7-Zip → NAS]      ──HTTPS──┐
[Офис: ваш .bat + Send-BackupReport] ───┼──> [VDS: backup_bot (приёмник + SQLite + бот)] ──> Telegram
[Офис: ...]                     ────────┘         └─ сторож: «бекап не пришёл вовремя»
```

* Каждый бекап отправляет отчёт на сервер: статус, код 7-Zip, размер, длительность, свободное место и строки с ошибками.
* Бот сразу присылает уведомление: ✅ успех (без звука), ⚠️ предупреждения, ❌ ошибка, ↩️ восстановление после сбоя.
* **Сторож** присылает ⏰, если от задания нет отчёта дольше `интервал × 1.25 + 15 мин`. Так ловятся выключенная машина, слетевшее задание в Планировщике и сменённый пароль. Пока проблема не решена, бот напоминает раз в сутки.
* Если «успешный» архив оказался вдвое меньше обычного, он помечается ⚠️.
* Утренняя сводка приходит в 09:00.
* Меню бота: **📊 Сводка · 🏢 Компании · ⚠️ Проблемы**. Дальше: компания → задание → последние 10 запусков, полный вывод 7-Zip, пауза и удаление.
* Задания регистрируются сами при первом отчёте, на сервере ничего настраивать не нужно.

```
server/   — код бота (Python 3.10+, aiogram 3) и Dockerfile
deploy/   — docker compose: бот + AmneziaWG + Traefik
agent/    — агент для Windows (Win 10/11, Server 2012 R2+; PowerShell 4+; VSS + 7-Zip -> NAS)
```

## 1. Сервер в Docker (VDS)

```
агенты офисов ──HTTPS──> traefik:443 ──> bot:8080            (приём отчётов, мимо VPN)
bot ──HTTP-прокси──> amnezia:8888 ──туннель AmneziaWG──> api.telegram.org
```
Контейнеров три:
* **traefik** — HTTPS с автоматическим сертификатом Let's Encrypt. Наружу открыты только 80 и 443, и пропускаются только `/api/report` и `/health`.
* **amnezia** — клиент AmneziaWG и прокси tinyproxy. Через него бот ходит в Telegram. Модуль ядра не нужен, туннель работает в userspace.
* **bot** — приёмник отчётов и Telegram-бот. Данные хранятся в docker-томе `bot-data`.

Если VPN «моргнёт», приём отчётов продолжает работать: он идёт мимо туннеля. Бот сам дождётся, когда Telegram снова станет доступен.

### 1.1. Подготовка
1. **Бот в Telegram:** напишите [@BotFather](https://t.me/BotFather) команду `/newbot` и сохраните токен.
2. **Домен:** создайте A-запись `backup.ваш-домен.ru` с IP вашего VDS. Если своего домена нет, подойдёт бесплатный поддомен, например duckdns.org. Порты 80 и 443 должны быть открыты.
3. **Конфиг AmneziaWG:** в приложении Amnezia выберите сервер → «Поделиться» → формат **AmneziaWG** (обычный `.conf`, не ссылка `vpn://`). Сохраните файл как `deploy/amnezia/config/awg0.conf`.
   * Строку `DNS =` и IPv6-адреса контейнер уберёт сам.
   * По умолчанию (`AllowedIPs = 0.0.0.0/0`) весь трафик контейнера amnezia идёт в туннель. Этого достаточно, потому что через него ходит только бот.
4. Нужен Docker с плагином compose (`docker compose version`).

### 1.2. Запуск
```bash
cd deploy
cp .env.example .env
nano .env                      # DOMAIN, ACME_EMAIL, BOT_TOKEN, ADMIN_IDS
chmod 600 .env amnezia/config/awg0.conf
docker compose up -d --build
```
Первая сборка займёт несколько минут: собирается AmneziaWG из исходников.

Проверка:
```bash
docker compose ps                              # amnezia должен стать healthy
docker compose logs amnezia | head -30         # «Внешний IP через туннель: …» — IP VPN-сервера
docker compose logs -f bot                     # «подключён к Telegram как @…»
curl https://backup.ваш-домен.ru/health        # {"ok": true}
```
Если `ADMIN_IDS` ещё не известен, оставьте его пустым и напишите боту `/start`. Бот ответит вашим id. Впишите его в `.env` и выполните `docker compose up -d`.

### 1.3. Полезное
* Обновить бота после изменения кода: `docker compose up -d --build bot`.
* Пересобрать AmneziaWG на свежей версии: `docker compose build --no-cache amnezia && docker compose up -d amnezia`.
* Резервная копия базы: `docker compose cp bot:/data/backup_bot.sqlite3 ./backup_bot.sqlite3`.
* **VDS за границей и VPN не нужен:** в `.env` задайте пустые `COMPOSE_PROFILES=` и `TELEGRAM_PROXY=`. Контейнер amnezia тогда не запускается, бот ходит в Telegram напрямую.
* **На сервере уже есть свой Traefik:** удалите сервис `traefik` из `docker-compose.yml`. В секции `networks` замените `web` на `external: true` с именем сети вашего Traefik. В метках бота поменяйте `traefik.docker.network`, `entrypoints` и `certresolver` на свои.

### 1.4. Компании
В боте:
```
/add_company ООО Альфа
```
Бот ответит токеном. Этот токен прописывается на всех машинах этой компании. Другие команды: `/tokens` (все токены), `/rename_company Старое = Новое`, `/check` (проверить пропуски прямо сейчас). Удалить компанию или посмотреть её токен можно кнопками в 🏢 Компании.

### 1.5. Без Docker (systemd + Caddy)
```bash
sudo useradd -r -m -d /opt/backup-bot backupbot
sudo cp -r server/* server/.env.example /opt/backup-bot/
cd /opt/backup-bot
sudo -u backupbot python3 -m venv .venv
sudo -u backupbot .venv/bin/pip install -r requirements.txt
sudo -u backupbot cp .env.example .env && sudo -u backupbot nano .env && sudo chmod 600 .env
sudo cp backup-bot.service /etc/systemd/system/ && sudo systemctl daemon-reload && sudo systemctl enable --now backup-bot
```
Для HTTPS положите `server/Caddyfile.example` в `/etc/caddy/Caddyfile`. Если Telegram доступен только через прокси, укажите его в `.env`: `TELEGRAM_PROXY=socks5://…` или `http://…`.

### 1.6. Сервер, где Traefik и AmneziaWG уже работают (`deploy/shared-host`)
Если на сервере уже есть свой Traefik (занимает 80/443) и AWG-прокси с HTTP CONNECT (`awg:3128`), стек из `deploy/docker-compose.yml` не нужен — поднимается только бот:
* приём отчётов идёт через внешний Traefik по сети `backup_proxy` (у Traefik должны быть entrypoints `web`/`websecure` и certresolver `le`);
* в Telegram бот ходит через внешний AWG-прокси по сети `awg_backup` — второй AWG-клиент с тем же ключом уронил бы туннель.

Обе сети создаются внешними стеками заранее (`external: true`).
```powershell
pwsh ./deploy/shared-host/deploy.ps1 -VdsHost my-vps          # доставить файлы в /opt/backup_bot (.env создаётся из примера один раз)
ssh my-vps "nano /opt/backup_bot/.env"                        # DOMAIN, BOT_TOKEN, ADMIN_IDS
pwsh ./deploy/shared-host/deploy.ps1 -VdsHost my-vps -Up      # собрать и запустить
```
Скрипт трогает только контейнер `backup-bot`. При каждом деплое он собирает архив агента для страницы установки и подставляет в установщик адрес `https://<DOMAIN>` из `.env` сервера.

## 2. Агент (Windows в офисах)

### 2.1. Как устроено
Задания описываются в файле `C:\BackupAgent\jobs.psd1`, установщик превращает их в задачи Планировщика (папка `\BackupAgent\`, запуск от SYSTEM). Каждый запуск:

1. ждёт своей очереди: на машине задания выполняются строго по одному;
2. делает **снимок тома (VSS)** — базы 1С, PST и открытые документы читаются со снимка, пользователей выгонять не нужно;
3. архивирует 7-Zip во временную папку (`C:\BackupAgent\data\staging`), проверяет архив (`7z t`), удаляет снимок;
4. копирует архив на **NAS** (`NasRoot\ИмяЗадания`) через временное имя `.partial` со сверкой размера;
5. удаляет старые копии на NAS (`KeepDays`, но минимум `MinKeep` последних) — **только после удачной копии**;
6. отправляет отчёт в бот (с пометкой 📸, если архив сделан со снимка).

Если снимок не удался (нет прав, не NTFS, сетевой источник), архив всё равно делается — без снимка, с ⚠️ и причиной.

Снимок файловой базы 1С — это её состояние «как при внезапном отключении питания»: 1С обычно такое переживает, но гарантии нет. Бекап 1С ставьте на ночь и раз в месяц проверяйте восстановление (развернуть копию, «Тестирование и исправление»).

Требования: Windows 10/11 или Server 2012 R2+ (PowerShell 4.0+; WMF 5.1 не обязателен), права администратора на установку. 7-Zip установщик поставит сам.

### 2.2. Установка
1. Скачайте агент со страницы установки `https://<домен сервера>/` (архив собирается из `agent/` при каждом деплое, адрес сервера в нём уже прописан) или скопируйте папку `agent`. Распакуйте на локальный диск: после запроса прав администратора сетевые диски, подключённые буквой, не видны.
2. Дважды кликните `Install.cmd`. Он запросит права администратора и:
   * скопирует агент в `C:\BackupAgent` и закроет папку от всех, кроме администраторов и SYSTEM (там токен и пароли);
   * поставит 7-Zip, если его нет;
   * спросит адрес сервера и **токен компании** (бот: 🏢 Компании → компания → 🔑 Токен) и проверит его — покажет название компании;
   * спросит сетевую папку NAS и проверит запись от SYSTEM. Если NAS требует логин — сохранит логин и пароль в Диспетчер учётных данных Windows (хранилище SYSTEM);
   * проверит, что снимки VSS работают;
   * создаст служебную задачу `_Sync` и откроет `jobs.psd1` в Блокноте — опишите задания, сохраните и закройте, они сразу применятся.

Повторный запуск `Install.cmd` — перенастройка (текущие значения предлагаются по умолчанию).

### 2.3. Задания: `jobs.psd1`
```powershell
@{
    '1C_Buh' = @{ Sources = 'D:\1C\Buh'; Exclude = '1Cv8tmp.1CD'; Schedule = 'Daily 01:00'; KeepDays = 30 }
    '1C_ZUP' = @{ Sources = 'D:\1C\ZUP'; Exclude = '1Cv8tmp.1CD'; Schedule = 'Daily 01:00' }
    'Docs'   = @{ Sources = 'D:\Docs', 'D:\Scans'; Exclude = '*.tmp', '~$*'; Schedule = 'Daily 22:00' }
}
```
| Параметр | По умолчанию | Что делает |
|---|---|---|
| ключ (`'1C_Buh'`) | — | Имя задания, так оно видно в боте |
| `Sources` | обязательный | Папки/файлы, можно несколько и с масками |
| `Schedule` | обязательный | `'Daily 01:00'`, `'Daily 09:00, 18:00'`, `'Every 4h'`, `'Every 4h from 08:00'`, `'Weekly Mon,Thu 02:00'` |
| `Exclude` | — | Маски исключений |
| `Destination` | `NasRoot\Имя` | Своя папка назначения вместо NAS по умолчанию |
| `KeepDays` / `MinKeep` | 14 / 3 | Удалять копии старше N дней, но оставлять минимум 3 последних |
| `Password` | — | Пароль на архив (шифруются и имена файлов). Пишите открытым текстом — при применении заменится зашифрованным |
| `UseVss` | `$true` | `$false` — без снимка тома |
| `Format` / `Level` | 7z / 5 | Формат и степень сжатия |
| `Test` | `$true` | `$false` — не проверять архив после создания |
| `Enabled` | `$true` | `$false` — временно отключить задание |

Интервал для сторожа (когда бекап считать пропавшим) вычисляется из `Schedule` сам. Два задания на одно время не мешают друг другу — второе подождёт первое.

**После правки `jobs.psd1`** ничего запускать не нужно: служебная задача `_Sync` раз в 10 минут проверяет, изменился ли файл, и сама создаёт/меняет/удаляет задачи Планировщика и шифрует пароли архивов. Итог приходит в бот заданием «jobs.psd1»: ✅ применено или ❌ с ошибкой (при ошибке задачи не трогаются). Сторож за этим заданием не следит.

```bat
C:\BackupAgent\Install.cmd -Apply      &rem применить сразу и показать ошибки на экране
C:\BackupAgent\Install.cmd -List       &rem задачи, последний и следующий запуск
C:\BackupAgent\Install.cmd -Run 1C_Buh &rem запустить сейчас (от SYSTEM, как Планировщик) и показать лог
```
Задачи в Планировщике (папка `\BackupAgent\`) руками не правьте — их перезапишет применение `jobs.psd1`. Общие настройки (NAS, `UseVss`, `KeepDays`, `StagingDir` и др.) — в `C:\BackupAgent\agent.config.psd1`, см. `agent.config.example.psd1`.

### 2.4. Сетевые папки и пароли
Сетевые пароли в файлах агента не хранятся — только в **Диспетчере учётных данных Windows**, в хранилище SYSTEM (задания работают от SYSTEM, Windows сама подставит логин при обращении к `\\сервер`). В домене паролей не нужно: дайте компьютеру доступ к шаре.
```bat
C:\BackupAgent\Install.cmd -Credential \\192.168.1.20\Docs  &rem сохранить логин/пароль и проверить доступ от SYSTEM
C:\BackupAgent\Install.cmd -Credentials                     &rem для каких адресов сохранены пароли
C:\BackupAgent\Install.cmd -RemoveCredential 192.168.1.20   &rem удалить
```
Сетевые папки можно указывать и в `Sources` — снимок VSS для них не делается (это штатно, без ⚠️). Если доступа нет, ❌ придёт с подсказкой, какую команду выполнить.

Вручную, без `jobs.psd1`: `Backup-Job.ps1 -Job "test" -Source "D:\Docs" -Destination "\\nas\backup\test" -IntervalHours 24` (параметры командной строки важнее файла). Коды выхода: 0 — ок, 1 — предупреждения, 2 — ошибка. Логи 7-Zip: `C:\BackupAgent\data\logs`, журнал агента: `C:\BackupAgent\data\agent.log`.

### 2.5. Свои .bat вместо агента: только отчёт
Добавьте две строки после вызова 7-Zip:
```bat
"C:\Program Files\7-Zip\7z.exe" a "E:\Backup\1c.7z" "D:\1C" > "C:\BackupAgent\data\logs\1c.log" 2>&1
set RC=%ERRORLEVEL%
powershell -NoProfile -ExecutionPolicy Bypass -File "C:\BackupAgent\Send-BackupReport.ps1" -Job "1C_base" -ExitCode %RC% -ArchivePath "E:\Backup" -LogFile "C:\BackupAgent\data\logs\1c.log" -IntervalHours 24
```
* `-ArchivePath` принимает файл архива или папку. Для папки берётся самый свежий файл. Если свежего архива нет, отчёт будет ❌ даже при коде 0.
* Из `-LogFile` в уведомление попадают строки с ошибками. Кодировка (UTF-8 или cp866 от cmd) определяется сама.
* `-StartedAt "%DATE% %TIME%"`, сохранённый в начале bat, позволит считать длительность.

### 2.6. Если сервер недоступен
Отчёт сохраняется в `C:\BackupAgent\data\queue` и отправляется при следующем запуске любого задания на этой машине. Повторная отправка не создаёт дублей. Журнал агента: `C:\BackupAgent\data\agent.log`.

## 3. Как читать статусы

| | Значение | Что обычно означает |
|---|---|---|
| ✅ | 7-Zip вернул 0, архив прошёл проверку | — |
| ⚠️ | 7-Zip вернул 1, не найдена часть источников, не удался снимок VSS или архив подозрительно мал | Снимок не создан (причина в сообщении) и файлы были заняты; источник переехал |
| ❌ | Код 2+, архив не создан, не прошёл `7z t`, не скопировался на NAS или скрипт упал | Нет места, NAS недоступен или сменился пароль NAS (`Install.cmd -Credential`), неверный путь |
| ⏰ | Отчёта нет дольше ожидаемого | Машина выключена, задание в Планировщике отключено или сломано |
| ⏸ | Пауза, пропуски не отслеживаются | Офис закрыт на праздники и т.п. |
